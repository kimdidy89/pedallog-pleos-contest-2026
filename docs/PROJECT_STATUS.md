## 목적

제품의 핵심은 브레이크·속도 자동 기록, 별도 서버 지속 동기화, 문제 발생 후 시각별 조회다. 알람·음성 경고·오조작 판정은 범위에서 제외한다. 현재 0.10 시제품을 기준으로 공모전 제출 자료도 준비했다.
`docs/FUNCTIONAL_SPEC.md`에 사용자 흐름·자동 실행·수집 시각·로컬 내구 저장·서버 ACK·재전송·조회·인수 시험을 정의했다.

## 공모전 자료 준비

- `submission/2026-11-09/`: 16쪽 소개서 PDF·PPTX, 58초 휴대폰 세로 실제 앱 모의 시연 영상, 실행 안내·발표 대본·예상 질문·체크리스트.
- 공식 기획서 8개 항목과 개인 참가자 신청서 초안을 갱신했다. 신청서·메일과 개인용 APK 파일명은 Git 제외 위치에 보관한다.
- 현재 구현과 개발 계획을 구분한다. 연락처·일반 부문·앱명 페달로그를 반영했다. 동의·서명·날짜와 소스·APK 다운로드 주소가 남아 있다. 아직 접수하지 않았다.
현재 구현은 0.10 Compose·Material3 네이티브 화면을 갖춘 수동 로컬 진단 시제품이다. 자동 시작·화면과 독립된 수집·서버·동기화·전체 서버 이력 조회는 아직 미구현이다. 기기에 실제 생성된 기록 파일 목록과 원본 내보내기를 제공한다.

디자인 개발을 시작했다. 공개 UI/UX Pro Max를 프로젝트 범위로 설치하고, Shadcn Admin의 최소 UI 구성요소로
`dashboard/`에 한국어 모의 조회 화면을 만들었다. Pretendard와 색상·아이콘·라이선스는 `assets/`에서 공유하며
Android 소스에도 적용했다. 웹은 실제 서버 기록을 읽지 않는다. 기존 제출용 APK/영상과 새 소스 빌드는 구분한다.

사용자 지적에 따라 차량용 Android 앱 중심으로 바로잡았다. 웹 추가 개발과 미리보기 서버를 중지했다.
`NativeDashboard`의 기록 상태·운행 이력·설정을 실제 APK로 구현하며 가로 화면에서는 상태와 그래프를 나란히 표시한다.

사용자 추가 결정에 따라 카카오·네이버 간편가입의 1차 데모를 제공한다. 실제 SDK/외부 인증 없이 필수 동의 선택·체험 프로필 유지·로그아웃을 확인하는 흐름이다. 실제 회원 인증이나 서버 접근 권한을 구현한 것으로 설명하지 않는다. 최신 화면과 검증은 `artifacts/easy-records/`를 따른다.

브랜드 인트로와 3D 렌더 스타일의 여우 캐릭터로 기록·시점 조회·체험을 설명하는 3장면 소개를 추가했다. 소개는 오프라인 네이티브 UI이며 이미지/프롬프트/해시는 assets/intro에 보존한다.
홈의 지난 기록 보기, 날짜별 카드와 날짜 선택, 쉬운 속도·브레이크 문장, 처음/가장 빠를 때/마지막·재생/멈춤을 제공한다. 그래프와 파일 정보는 선택하여 펼친다. 홈 직접 체험/차량 연결과 원본 내보내기는 유지한다.
라이트/다크/기기 설정을 앱 전체에 적용하며 선택을 기기에 보존한다. 실제 간편가입과 자동 시동 기록, 서버는 여전히 후속 단계다.
